Working across many notes, without tabs

A friend wants tabs so he can hop between the notes he is working on. You want to avoid tabs because they are one more thing to open, close, tidy and remember. This page lists ways to give him the fast hop without handing him a row of things to keep clean.

What he actually asked for
  • Swap between recent notes quickly. One or two keystrokes, not a search.
  • Hold several notes "open" at once. A working set for one piece of work.
  • He moves along links and the graph, so the set grows as he follows them.
Why tabs are the wrong shape
  • Every open needs a matching close, or the strip fills and becomes noise.
  • Two parallel histories: the tab's own and the app's Back. Which one does ⌘[ mean?
  • Restoring, reordering, duplicate tabs of one note, "close others": all maintenance.
  • A strip of titles competes with the note title band and the recording chip.
What Cilica has today
  • A Back button in the band (50-deep stack). No Forward, no key.
  • Recent notes in the empty ⌘K palette.
  • Connections under each note and the ⌘G graph.
How each idea is judged
Nothing to closeThe set looks after itself. Forgetting it costs nothing.
One gesture to hopReaching the last few notes takes a key or a click, no typing.
Follows linksGoing A → B → C via links keeps that path in reach.
Fits the roomNo new chrome fighting the title band, the assistant or the sidebar.
Family 1 · Hop by time

Make "the last few notes" one keystroke away

The list is your own history. Nobody curates it, it just exists.

1.1

Note switcher on Ctrl+Tab

Core

Hold Ctrl, tap Tab to walk back through notes by most recent use, release to open. A single tap swaps to the previous note and back again, like ⌘Tab between apps.

This is what tabs are mostly used for, with none of the strip. The overlay shows title, category and "edited 4 min ago". Ctrl⇧Tab walks the other way. Same list as the palette's Recent notes, so there is one idea of "recent".

Core

Following links is a path, and the path is already recorded in the router stack. Today it is one-way and mouse-only. This fixes the "I went three links deep, take me back two" case without anything new on screen.

Family 2 · Stay in place

Look at another note without leaving this one

Much tab use is "keep this open so I can glance at it". If the glance never leaves the current note, there is nothing to come back to.

2.1

Peek a link

Core

Hover a [[link]] with ⌘ held, or press Space on a link in Connections, to float the note over the current one. It is editable. Esc or moving away closes it; click its title to go there for real.

Quick Look for notes. Answers "what did I write in Pricing again?" without a hop. Also works on graph nodes and palette rows.

2.2

Open beside, two at most

Maybe

⌘-click a link (or "Open beside" in its menu) to split the canvas: this note left, that one right. Clicking another link on the right replaces it. Close the split and it is gone.

For writing while referencing. Capped at two so it never becomes a pane manager. The assistant panel already pushes the editor, so width gets tight on laptops; the split would hide the assistant while open.

2.3

Sliding notes

Bold

Clicking a link opens the note as a new column to the right; older columns fold into thin spines with their titles. Clicking a spine unfolds it. Following a link from an earlier column drops everything after it.

The trail and the working set become one thing, and it prunes itself because branching off cuts the tail. It is a strong fit for link-heavy writing but changes the whole canvas, and every other view (transcript, recording, assistant) would need to fit in a column.

Family 3 · Hop by meaning

Let the links decide what is nearby

Cilica already knows which notes belong together. The working set can be derived from that instead of from what was left open.

3.1

Trail in the band

When you arrived by following links, the band shows the path in small text: Q1 hiring › Acme kickoff › Pricing v2. Click any step to go back to it. Opening a note from the sidebar or palette starts a new trail.

The visible form of 1.2. It shows up only when there is a path, so there is no empty chrome. Long trails collapse the middle.

Neighbour hop

⌥⌘↓ opens a small list of this note's neighbours (links out, links in, recent ones first) and you pick one with a number. Same data as Connections, reachable without scrolling to the bottom.

Family 4 · Pick up where you left off

Remember the set across days, without saving it

Tabs also act as "what I was doing yesterday". These ideas cover that without a strip that survives forever.

4.1

Sessions that form themselves

Maybe

Cilica groups the notes you opened into sessions, split by gaps of an hour or more. Home shows the last few: "Yesterday afternoon · 6 notes · Pricing, Acme kickoff, Tiers…". Click to reopen the most recent and fill the switcher (1.1) with the rest.

The working set exists, but only in hindsight, so nothing is ever left open. Naming one turns it into a saved set, which is optional.

"Open what I was working on with the Acme deal on Tuesday." The assistant already has note search and history; it would also need the visit log. It answers with a short list to open, or fills the switcher.

Not a replacement for a fast key, but it makes the visit history useful for vague recall. Nearly free once 1.1 records visits.

4.3

A hub note, made by hand

No feature. Show the friend a pattern: a "Desk" note with links to what he is working on, pinned to the top of a category, opened with ⌘K. Peek (2.1) makes it work well.

Zero code and fits the Markdown-and-links spirit. But it is maintenance, which is exactly what you want to avoid, just moved into a note.

4.4

A note in its own window

Later

"Open in new window" lets a note float as a small second window. macOS already switches windows with ⌘` and Mission Control.

Hands the job to the OS, which people already know how to manage. Costs a lot in Tauri: a second editor, shared state, focus rules, recording and assistant per window.

Tab-shaped ideas that keep the maintenance

Pinned notes with ⌘1–⌘9

Fast, but someone has to pin and unpin. Stale pins pile up like tabs. If added later, cap at 3 and expire pins not opened in a week.

A tab strip that closes old tabs itself

Solves clutter but tabs vanish under you, and it still adds a row of chrome and a second history. Ctrl+Tab gives the same reach with no row.

Named workspaces

Good for big projects, but it is a whole object to create, fill and keep current. 4.1 gets most of the value by deriving it.

Recommendation

Three small pieces, then see if he still wants tabs

Each step is useful on its own and none adds anything to close. Ship the first, give it to your friend for a week, and only go further if he still reaches for something it does not cover.

Step 1 · Hop

Ctrl+Tab switcher + real Back / Forward

1.1 and 1.2, with 1.3 as a freebie. One recency list (a visit log in the router, persisted) feeds the switcher, the palette and later sessions. Covers "swap between recent notes" directly.

Step 2 · Glance

Peek a link

2.1, plus the trail in the band (3.1) if the trail turns out to matter. Covers "I keep a note open just to look at it", which is most of what is left.

Step 3 · Only if asked

Open beside, or sessions

If he really needs two notes on screen while writing, 2.2 capped at two. If the gap is "what was I doing yesterday", 4.1. Sliding notes (2.3) only if you want it as the app's identity.

Open questions about your friend

Answers that would change the pick

Does he need two notes visible at the same time, or just to switch fast?Visible at once points to 2.2. Switching fast is fully covered by step 1.
Keyboard or mouse?A mouse user gets little from Ctrl+Tab and much more from 1.5 or 3.1.
Should the set still be there tomorrow, or after a restart?If yes, persist the visit log and add 4.1. If not, in-memory history is enough.
How many notes is "many": three or fifteen?Three fits a switcher. Fifteen suggests the notes belong to a project, where a category or sessions fit better than any hop.
Which app is he comparing with?Obsidian-style tabs and VS Code-style tabs are used differently; knowing which tells us which habit to replace.
