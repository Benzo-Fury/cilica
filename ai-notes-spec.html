Build spec · v0.2 · 11 Nov 2026

Cilica

A local-first desktop notes app with an AI assistant and a meeting summariser. The assistant can read and edit every note; the summariser records calls without a bot, transcribes them on-device with speaker labels and writes them up as notes. This page is the brief for agents designing and building it.

Tauri 2 + Rust core macOS 14.4+ · Windows 10/11 · Linux (PipeWire) Local-first SQLite Records system + mic audio

Decisions on the open questions

QuestionDecision
UI frameworkTauri 2: all logic in Rust crates, UI in React + TypeScript in the OS webview. Pure-Rust UIs (GPUI, Iced, Slint, Dioxus native) would mean building a rich Markdown editor, drag and drop, blur and spring animation from scratch. Tauri keeps the binary small (no bundled Chromium) and gives native window vibrancy through window-vibrancy. Anarlog uses the same split.
Meeting audio captureCapture two streams, never integrate with Zoom: the mic (you) and system output (everyone else). This is app-agnostic, so Zoom, Meet, Teams, WhatsApp and Slack all work with no bot. Per-OS APIs are in Audio capture.
Claude subscriptionAnarlog does not handle Claude tokens. It runs the user's installed claude CLI headless (claude -p --output-format stream-json), so Claude Code's own login is used. Copy that as an opt-in Claude Code bridge, but make API key the default. Anthropic's 2026 terms limit subscription use to Claude Code and claude.ai, so label the bridge experimental. See Providers.
AI guardrailsAdopt all six ideas, arranged as permission tiers: reads run freely, additive writes apply with undo, edits show a diff, destructive actions need confirmation. Everything is versioned, soft-deleted and logged. Add transcript prompt-injection isolation. See Guardrails.
Bottom sidebarListening toggle, Scheduled tasks, Saved people, AI activity, Trash, Settings.
Speech-to-textLocal Whisper (whisper.cpp) is the default engine, as in Anarlog's on-device mode. Audio never leaves the machine. Cloud engines stay available as an option.

Performance budgets

  • Installer under 20 MB, excluding downloadable speech models.
  • Idle memory under 150 MB. Cold start to interactive under 1 s.
  • Animations hold 60 fps (120 on ProMotion). Only transform/opacity animate; never width/height/top.
  • Live transcript lags speech by under 3 s with the local engine.

Left sidebar

  • Top row: New note, New category (inline-editable name), Record. Search appears below on ⌘P and hides via its own button or Esc; open/closed state persists.
  • Note rows: title, relative date, one-line AI snippet, a mic glyph for meeting notes, a pulsing red dot while recording.
  • Categories: drag notes in or out (dnd-kit, animated drop), drag to reorder categories, click the header to collapse. Uncategorised notes sit at the top under “Notes”.
  • Bottom: Scheduled tasks (name, next run, status dot), Saved people, AI activity, Trash, Settings, and a Listening row that toggles auto-detect and shows a live mic level during recording.
  • Collapses fully with ⌘\.

Note view

  • Header: editable title, a SegmentedSlider (Notes ↔ Transcript, animated thumb, ⌘E), recording timer and Stop while live, overflow menu (export Markdown, copy, history, move to trash).
  • Notes panel: TipTap Markdown editor. The user can type during a meeting; those jottings are kept and woven into the AI summary, as Granola does.
  • Transcript panel: segments grouped by speaker with timestamps, auto-scrolling while live (pauses when the user scrolls up). Click a speaker chip to rename or link a Saved person.
  • History: version list with author (you or AI) and a diff against current; one-click restore.

Right sidebar: assistant

  • Toggled with ⌘J; the panel animates in and pushes the editor (it does not overlay it).
  • A context line at the top shows what the assistant can see (“Viewing: Acme kickoff · Transcript”).
  • Empty state: 3–4 prompt chips generated from context. Meeting note: action items, follow-up email, per-person commitments. Sidebar or category selected: weekly digest, find duplicates. Chips are cached per note and refreshed after edits.
  • Tool calls appear inline as compact rows (“Searched 14 notes”). Proposed edits render as diff cards with Apply / Reject.

Recording flow

  1. Trigger. Manual: Record button, ⌘⇧R (global hotkey) or the tray menu. Automatic: the detector reports an allow-listed meeting app holding the mic for 5 s. The setting chooses between auto-start and ask first (an action toast), default ask first.
  2. New note. Titled “{App} meeting · {time}” and opened on the Transcript panel. A toast confirms with a Stop action.
  3. Capture. Mic and system streams start in parallel, are echo-cancelled and resampled, and are written to disk as they arrive, so a crash loses nothing.
  4. Live transcript. VAD splits speech into chunks; the engine streams partial then final segments to the UI as events. Mic segments are labelled You; system segments are labelled Others until diarization assigns Person 1, 2….
  5. End. Manual Stop, or the meeting app releases the mic for 15 s. A toast offers “Keep recording” for 10 s.
  6. Finalize. Full diarization pass, matching against Saved people voiceprints (suggested, never applied silently). Then the LLM writes the summary into the Notes panel, above any user jottings: Summary, Decisions, Action items (owner + due), Open questions. The view slides to Notes.

Speakers and Saved people

  • Each Person 1…n is a cluster of speaker embeddings for that meeting. Naming one offers “Save as person”, which stores the name and an averaged voiceprint.
  • Later meetings compare clusters to saved voiceprints (cosine similarity above a tuned threshold) and suggest “Is Person 2 Sam?”.
  • Saved people page: name, voiceprint sample count, meetings they appeared in, merge/rename/delete.
  • In-person meetings (one mic, many speakers): diarize the mic channel as well.

AI assistant

Context, without being told

Each turn starts with a compact <view> block built by the frontend: open note id and title, active panel, selected text, selected category, search query, recording state. Larger content (note bodies, transcripts) is fetched by the model through tools, so turns stay cheap.

Tools

TierTools
Readsearch_notes, get_note, get_transcript, list_categories, list_people, list_tasks, get_note_history
Additivecreate_note, create_category, move_note, rename_category, label_speaker, create_task
Editedit_note (takes a patch, never a full rewrite), rename_note
Destructivetrash_note, merge_notes, delete_category, delete_person, any write touching more than 5 notes

The tool registry lives in the agent crate and is the only write path for AI. The same registry is exposed over MCP for the Claude Code bridge.

Guardrails

Applied per tier

  • Read: runs freely.
  • Additive: applies at once, with an Undo toast.
  • Edit: a diff card; accept the whole change or per hunk.
  • Destructive: a confirm card naming every affected note. This one cannot be switched off.

Always on

  • Version history: snapshot before every AI write.
  • Soft delete: Trash keeps items 30 days.
  • Audit log: AI activity lists every tool call with arguments, result and Undo.
  • Turn undo: ⌘Z reverts a whole AI turn as one step.
  • Prompt-injection isolation: transcripts and note bodies reach the model wrapped as quoted data. A participant saying “delete all my notes” must never get past the destructive-tier confirmation, whatever the model decides.
  • Scheduled tasks only propose: they run without the user present, so every change they suggest waits as a proposal.
  • Limits: at most 20 writes per turn. No network or shell tools.
  • Settings can promote Edit to auto-apply (still versioned). Destructive cannot be promoted.

AI providers and auth

ProviderHow it works
Anthropic API keyDefault. Key in the OS keychain. Direct Messages API with streaming and tool use.
OpenAI-compatibleBase URL + key: OpenAI, OpenRouter, Groq, LM Studio.
OllamaLocal models, no key. Assistant quality varies with model tool-use support.
Claude Code bridgeExperimental, opt-in. Detect claude on PATH and check its auth status. Spawn claude -p --output-format stream-json with --resume for threads and --mcp-config pointing at our local MCP server, with allowed tools limited to ours (no Bash, no file edits). The app never reads or stores Claude credentials.
Policy riskSince February 2026, Anthropic's consumer terms say Free/Pro/Max OAuth tokens may only be used in Claude Code and claude.ai, and in April 2026 subscription access was cut off for third-party harnesses. Running the user's own CLI is how Anarlog does it, but it may still breach those terms and put the user's account at risk. Re-check Anthropic's current terms before shipping this path, and show the warning in the opt-in dialog.

Scheduled tasks

  • A task has a name, prompt, scope (all notes, a category, or the last N days), schedule (every N days, weekly on a day, or daily at a time), and an on/off switch.
  • The runner lives in Rust: it stores next_run_at and runs missed tasks at the next launch. It never runs while recording.
  • A finished run raises a toast and puts a badge on the task in the sidebar. Opening it shows the report view.

Default: Notes review (every 3 days, enabled)

  • Merge: groups of notes that cover the same topic, with a preview of the merged note.
  • Trim: content that could be dropped, shown in the DiffView component (git-style red/green, line numbers in mono).
  • Delete: notes that look stale or empty, with the reason.
  • Each suggestion has Apply / Dismiss; “Apply all” still goes through the destructive confirm card. Dismissed items are remembered so they are not suggested again.

Toasts

An in-house module at src/lib/toast/, modelled on the behaviour of Sileo (MIT): spring physics and a gooey morph from a compact pill into an expanded card. Depends only on React and Motion. Re-implement it; do not vendor Sileo.

toast("Saved")
toast.success("Summary ready", { description: "Acme kickoff" })
toast.error("Mic unavailable", { description: "Choose another input in Settings." })
toast.action("Zoom meeting detected", { action: { label: "Record", onClick } })
toast.undo("Moved 3 notes to Client work", { onUndo })
toast.promise(summarise(), { loading: "Summarising…", success: "Summary ready", error: "Summary failed" })
  • Rust can raise toasts through a typed toast event, so backend jobs (scheduler, detector, STT errors) use the same component.
  • Top-center. At most 3 visible, the rest queue. New toasts spring in and the stack reflows.
  • Timing: 4 s default, 8 s for errors; toasts with an action stay until 6 s after the pointer leaves. Timers pause on hover and on window blur. Swipe or Esc dismisses.
  • Reduced motion uses a plain fade. Colours, surface and icon styling come from the design system.

  • Each crate has a short README: purpose, public API, what it must not depend on. domain depends on nothing app-specific; src-tauri only wires crates together.
  • A feature folder owns its components, hooks and state. UI components never call IPC directly; feature hooks do.
  • Every crate is testable without a window: audio and STT run against recorded fixture WAVs, the agent against a mock provider.

Build order

  1. Foundation. Tauri shell, vibrancy window, tokens, motion presets, ui/ components, toast library, keybind registry, command palette.
  2. Notes. Store, sidebar with categories, drag and collapse, FTS search, TipTap editor, version history, Trash.
  3. Manual recording on macOS. Mic + process tap, AEC, local Whisper, live transcript, end-of-meeting summary.
  4. Speakers. Diarization, speaker chips, Saved people, voiceprint suggestions.
  5. Assistant. API-key providers, view context, tool registry, tiers, diff cards, AI activity, turn undo.
  6. Auto-detect and other platforms. Meeting detection on all three OSs, Windows and Linux capture, permissions onboarding.
  7. Scheduled tasks. Runner, task editor, Notes review report with DiffView.
  8. Ship. Claude Code bridge (experimental), updater, code signing and notarisation, performance pass against the budgets.
